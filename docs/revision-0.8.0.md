# Tidy 0.8.0 — conversations and reviewed file operations

Ask Tidy now keeps a visible local conversation. A separate reply composer sends the original user request and user follow-ups plus bounded recent question/answer context. Assistant questions are separate from user instructions and do not grant modification authority. New request resets the conversation. Errors preserve answers; replies generate a fresh proposal, invalidating any prior approval. Context is scoped to the current folder/session; it is not persisted across app restarts. Explicit confirmations and repeated answered clarifications are rejected with bounded model correction attempts.

A narrow exact path handles “Change all text files to .json” without model loading: inspect every indexed path, choose .txt/.text files recursively, preserve parent and stem, change the extension only, skip protected bundles/dependencies, check case-insensitive collisions and show at most 500 reviewed actions. Bytes are unchanged; a renamed file is not automatically valid JSON. Named exceptions/extra conditions use bounded AI investigation. The separate extension workflow permits requested extension changes while descriptive-name workflows continue preserving extensions.

The catalog now has 42 workflows, adding extension changes, copies and ordinary Unix file permissions. The native tool grammar supports structured copy and permission proposals. The model never runs a shell or executes changes. All actions reference discovered indexed IDs and require the same one-use explicit approval, source/root rechecks, journal and result verification.

Copies create an absent destination with no-follow/exclusive directory-relative handles. Originals remain intact. Copy bytes are verified against the pinned source; new files are private (0600), with fresh timestamps. This copies regular-file data, not resource forks, extended attributes or all original metadata. Copies are indexed separately with new IDs. Undo proposes native Trash for the verified copy, preserving the source. A failed/interrupted copy may leave a partial destination recorded in History; it is never silently removed. Inspect recovery steps manually.

Permission actions show exact old/new octal modes in approval and History. They use descriptor-based fchmod, recheck the file/mode, journal old/new modes atomically with the prepared step and verify the result. Undo restores the old mode only if the file is unchanged. Ordinary modes must retain owner-read access; special bits and hard-linked files are refused. No ownership, ACL, elevated privileges or arbitrary access commands are supported. Windows mode changes and safe filesystem execution remain unavailable pending their platform implementation; this build targets macOS.

Supported modification scope is regular indexed files in one authorized root, including recursive file selections. Moves/copies can create approved destination parent folders. Directory metadata mutation, cross-root operations, arbitrary content conversion, ownership/ACL changes and system-wide unrestricted manipulation are not implemented. Removal always uses native Trash, never permanent deletion. Git repositories, protected system areas, symlink/mount boundaries and application/dependency protections remain in effect.

The journal extension is additive: a permission_changes table with old/new mode evidence; existing steps are preserved. Legacy/unbound actions remain non-executable. Source backup was retained before installing this revision.

Validation: offline Rust workspace and test targets compile; frontend TypeScript/production build and macOS packaging pass; native worker rebuilt from the checksum-verified cached pinned llama.cpp source. Functional/model/file-operation tests were deliberately left to the user. The release checklist contains targeted regression commands and disposable manual scenarios.
